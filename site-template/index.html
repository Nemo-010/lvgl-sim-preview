lvgl-preview

Every image below was produced by a GitHub Actions run of this repository: Zephyr was built for the native simulator, an LVGL application ran against a capture sink, and the frames were read back out of the shared buffer. Nothing here is a mock-up.

128x64 monochrome OLED

Target board frdm_mcxa156. The panel geometry, pixel format and button codes were read from that board's devicetree, so the emulated panel is the real one: an SSD1306, 1bpp, vertically tiled, bit 7 first.

A colour panel, same sink

The same capture sink against the simulator's own 320x240 ARGB8888 display. The sink is not monochrome-specific: it forwards whatever the panel driver declares.

How it works

  • The sink is a Zephyr display driver, so it needs no changes to the application and works with any LVGL version.
  • It captures what display_write() was handed, so the preview is the real hardware path, not a parallel renderer.
  • Frames are published into a file-backed mapping. seq is written last, so a reader never shows a torn frame.
  • Monochrome packing, bit order and polarity are resolved on the device and stated in the frame header, because polarity is not derivable from the pixel format alone.
